# Intake template

Send this to the user in one message (translate to their language, drop the parts already answered). Fill in the engine-specific commands from `references/databases/<db>.md` so the user can copy-paste them.

---

To optimize this query properly I need a few facts. Rough numbers are fine; if you don't know one, run the command next to it.

**1. Database and exact version** (I'll read the docs for that version and only give you syntax that works on it)
- Engine and exact version (e.g. PostgreSQL 16.4, MySQL 8.0.36, SQL Server 2022 + compat level): `<version command>`
- Managed service? (RDS / Aurora / Azure SQL / Cloud SQL / self-hosted)

**2. Query**
- The full SQL exactly as the app runs it, with a realistic example of parameter values
- Is it generated by an ORM / prepared statement?

**3. Table structure and indexes** (for every table in the query)
- `<show create table command>`
- `<list indexes command>`

**4. Data volume**
- Rows and size per table: `<row count / size command>`
- For each column in WHERE / JOIN / ORDER BY / GROUP BY: how many distinct values, and how many rows a typical value matches: `<cardinality command>`
- Any skewed value (e.g. 90% of rows have `status = 'done'`)?
- Growth per day?

**5. Traffic**
- How often does this query run (normal and peak)?
- Current latency and target latency
- Writes per second on these tables (insert/update/delete)
- OLTP request path, background job, or report? Primary or replica?

**6. Current plan** (if you have it already)
- `<explain command>`

---

Do not include real customer data — schemas, counts and plans are enough.
